# Implementation Plan: Playground redesign (per-task office + Flow view)

**Branch**: `feature/LIBRE-3` | **Date**: 2026-10-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-playground-redesign/spec.md`

## Summary

The Playground becomes a building of per-owner floors, and each task (or project) gets an
**Oficina** tab with its own floor, drawn with pixtuoid's art ported to our SVG pixel
maps, plus a **Flujo** view (agent → tool calls → helpers graph + timeline). The daemon
gains two in-memory pieces: a bounded per-session activity history (200 entries, up to 64
sessions incl. recently ended ones; revises decision #80) served by
`GET /api/v1/activity/history`, and per-session token usage read incrementally from the
Claude transcript by the existing transcript watcher, added to `GET /api/v1/activity`.
No migration, no new dependency. Details in [research.md](research.md).

## Technical Context

**Language/Version**: Rust 2024 edition (`delilah-agents`, `delilah-daemon`); TypeScript +
React 19 (`app/`); Python 3 stdlib for the one-off art port script.

**Primary Dependencies**: existing only (axum, serde, tokio, chrono; Vite, vitest, Testing
Library; Tauri v2). No graphics or graph library.

**Storage**: none (in memory; no migration).

**Testing**:
- `cargo test -p delilah-agents` (usage parsing, `ToolEnded.failed`)
- `cargo test -p delilah-daemon` (activity log, history endpoint, token meter, watcher)
- `cd app && npx tsc --noEmit && npx vitest run` (art data, ramp, outfits, floor layout,
  flow model/layout, components)

**Target Platform**: macOS (Tauri app); the web UI in a preview for trying it.

**Project Type**: desktop app (daemon + web UI + shell).

**Performance Goals**: changes visible ≤ 2 s (SC-003), tokens ≤ 10 s (FR-025); no JS
animation loop; a floor with 4 leads + 12 helpers and a Flow graph of 400 nodes stay
smooth (one `<path>` per colour per sprite frame; history refetches use `after`).

**Constraints**: captions/targets ≤ 40 chars (cut in the adapter); art only from pixtuoid
(MIT) with notice; reduced motion; ≥ 12px type; readable at 1024 px window width.

**Scale/Scope**: ~10 live sessions, 64 logs × 200 entries (~13k entries, < 5 MB); 1 new
endpoint, 1 changed response, 1 new tab, 3 views (floor, building, flow).

## Design

### 1. Adapter (`delilah-agents`)

- `ActivityEvent::ToolEnded` gains `failed: bool`; `classify_activity` sets it for
  `PostToolUseFailure`. `Activity::apply` ignores it. Existing tests updated, one new.
- `transcript::usage_delta(bytes: &[u8], last_id: Option<&str>) -> UsageDelta { usage,
  consumed, last_id }` per [data-model.md](data-model.md): complete lines only; dedupe by
  `message.id`; `cache_read` outside `total`. Table tests: two content-block lines of one
  message count once; partial last line not consumed; non-assistant and bad lines
  skipped; missing fields = 0.

### 2. Activity log (`activity_log.rs`, `hooks.rs`, `session_api.rs`)

- Pure `ActivityLog` with `record(session, owner, at, event, is_live)` and
  `for_owner(owner, after)`. Tests: 201 entries → 200 and `dropped`; `seq` strictly
  increasing across sessions; the 65th session evicts the oldest non-live log and never a
  live one; `after` filters; owner filter.
- `hooks.rs`: where `classify_activity` already runs for a live Claude session, also
  record the event. `is_live` is computed before taking the log's lock (no
  `app.sessions` call under it). `Topic::Activity` is still emitted at once only when
  `Activity` changed (`activity_is_announced_on_change_only` keeps passing); an append
  that changes nothing (e.g. the second of two parallel calls) sets an
  `activity_dirty` flag that the transcript watcher's 1 s tick turns into one emit, so
  bursts coalesce and Flow stays within 2 s. New test: a no-change append is announced
  by the next tick, once. Shell sessions never reach this path.
- Entries are served through a daemon-side DTO `EntryView` with explicit snake_case
  tags (`tool_started`, …), not by serialising the adapter's `ActivityEvent` (which is
  kebab-case and belongs to the adapter crate).
- Cap: at most 64 logs; evict the non-live log with the oldest `last_at`; if all 64 are
  live, the log grows past 64 (live logs are never dropped).
- `GET /api/v1/activity/history` per [contracts/api.md](contracts/api.md); router tests
  with the existing `post` helper: hook → history has the entry; `after` returns only
  newer; unknown owner → empty; bad `after` → 400; an ended session's log is still
  returned with `live: false`.

### 3. Tokens (`tokens.rs`, `transcript_watch.rs`, `session_api.rs`)

- `transcript_seen` becomes `transcript_progress: Mutex<HashMap<id, TranscriptProgress
  { seen, meter: TokenMeter }>>` (one map, one prune in `tick`); the module doc is
  updated (the watcher now parses usage lines).
- In `check`, after the newline logic: take `meter.offset` under the lock, read up to
  1 MB from it outside the lock (`spawn_blocking`; first sight starts at 0 and catches
  up 1 MB per tick, so a restart never reads whole multi-MB files at once), parse with
  `usage_delta`, then re-lock and apply only if `offset` is unchanged
  (compare-and-advance: a concurrent `poke` and tick never count the same bytes twice).
  If `total` changed, emit `Topic::Activity`. Test: two concurrent checks on the same
  appended line count it once.
- `/activity` adds `tokens` for live sessions with a meter. `tokens` and `sessions` are
  independent maps (a session can have tokens and an empty activity); the existing
  `/activity` tests asserting `{"sessions": {}}` are updated in the same package.
- Tests (tokio, temp transcripts like the existing watcher tests): first sight counts
  existing lines; appended line updates within one tick and emits; partial line waits;
  shell session never metered; a transcript outside the projects folder is never read.

### 4. App data (`api.ts`, `useOffice.ts`, `useActivityHistory.ts`, `App.tsx`)

- `useOffice()` = today's `usePlayground` regrouped by owner (task or `@project`), with
  tokens. The bookkeeping is pure in `floorLayout.ts` (`assignSlots(prev, now)`,
  `trackLeavers(prev, now, at)`, `floorOrder(prev, owners)`), so it is tested without
  React; the hook only keeps the previous result in a ref. Floors newest on top; desk
  slots stable per owner; helpers that disappear become leavers for ~5 s.
- `useActivityHistory(owner)`: full fetch on mount, then `after=<last seq>` on each
  `activity` topic; merges per session; refetches fully on reconnect.
- `App.openTask(owner, target?)`: `target` may be `OFFICE`, otherwise a session id as now.

### 5. Art (`scripts/port-pixtuoid.py`, `art/*`, `PixelSprite`)

- The script reads `pack.toml` + the subset in research R6 from a local pixtuoid checkout
  (path argument), validates widths, remaps non-ASCII keys to free single chars, and
  writes `art/pixtuoid.ts` with a header (source URL, commit, "generated — do not edit").
  It also emits ramp fixtures used by `ramp.test.ts`.
- `art/ramp.ts` (OKLab lightness step), `art/outfit.ts` (seed, outfits, presets,
  `lookFor(project, sessionId)`, `roleLook(role)`), `art/kinds.ts`.
- `PixelSprite({ sprite | animation, recolour, scale, label? })`: merges runs into one
  `<path>` per colour; animations stack frames and step with CSS keyframes (duration =
  frames × frame_ms); `aria-hidden` (names live on the buttons around sprites).
- Tests: every generated sprite has equal-width rows and only palette keys; recolour
  changes B/P/H/S and their ramps; `lookFor` deterministic and equal for the same project;
  PixelSprite path count = distinct colours.

### 6. Floor, building, office tab (UI)

- Visual frame, toggle, tab, state colours, flow node and building row styles follow
  the app's design system as set out in [research.md R10](research.md) (user request: base
  the design on the design artifacts, which have no Playground of their own).

- `floorLayout.ts` (pure): grid of 2×2 pods (lead desks fill first, helpers next), aisle,
  lounge corner (sofa, table, pantry, plants); `seatPosition(slot)`, `loungePath(slot)`
  (3-point polyline), floor size grows by pods. Tests: stable slots across updates,
  growth, path endpoints.
- `Floor`: positioned desks (desk + chair + monitor glow + paper stack by tier + cup),
  characters as buttons with accessible names (`accessibleName` extended with tokens),
  `?` / `zzz` bubbles, captions (≥12px), leavers walking via CSS transitions per leg;
  empty state; `--stale` and hidden pause as today; reduced motion: no walking, leavers
  shown on the sofa then gone.
- `FloorMini` + `Building`: floors stacked, each a button (key, title, phase, up to 6
  miniature characters + "+N", waiting badge/highlight); top counter; empty state;
  stale banner. Main window: click → `openTask(owner, OFFICE)`. `PlaygroundWindow`: click
  → floor in place with a Back button and the toggle; lead click → `requestOpenTask`.
- `OfficeTab`: toggle (radio group "Oficina / Flujo", stored in `localStorage`
  `delilah.office.view`, try/catch), renders `Floor` or `FlowView` for the owner.
- `TaskTabs` kind `office` (icon), `TaskScreen` adds the fixed tab after Overview for
  tasks and projects.

### 7. Flow (UI)

- `flowModel.ts` (pure): entries → nodes/edges/timeline per research R8 (pairing by tool
  use id; failed; running vs unknown end; helper → lead; dropped/empty notes). Tests:
  parallel calls are two nodes; helper's tools attach to the helper; end without start
  ignored; ended session's running call becomes unknown.
- `flowLayout.ts` (pure): agents as a left-to-right tree, each agent's tools in rows
  beside it; positions depend only on order → stable. Tests: a node keeps its position
  when later events arrive.
- `FlowView`: SVG with `viewBox` pan (drag) / zoom (wheel, buttons, fit); nodes coloured by
  `KIND_COLOURS`, running ones with a pulsing outline (still with reduced motion); a
  details panel for the selection; `Timeline` list below (buttons with time, kind, tool,
  target), two-way selection; notes for dropped/none-since-start.

### 8. Removals and callers

- `Desk.tsx/.css`, `sprites.ts`, `Sprite.tsx/.css`, `poses.ts`, `usePlayground.ts` go;
  their tests are ported where the behaviour stays (`layout.test.ts` → captions,
  accessible names, helper roles; `PlaygroundView.test.tsx` → `Building.test.tsx`) and
  deleted where it does not (16×16 pose maps).
- Callers: `TaskTabs` consumers of `kind`, every `openTask` call site, and the
  playground window entry are updated in the same package as the API they use.

### 9. Docs

- `docs/decisions.md`: revise #80 (history kept in memory, 200 × 64), new: pixtuoid art
  (MIT; supersedes the "no third-party sprite sheets" part of #79), tokens from the
  transcript (fresh spend, deduped by message id), flow layout without a graph library,
  building + per-owner floors.
- `docs/status.md`, `docs/architecture.md` (activity log, tokens, endpoints, playground
  modules), `README.md` (Oficina tab, Flujo, building), `CREDITS.md`.

## Risks

- **Transcript format drift** (Claude Code changes usage fields): parsing is tolerant
  (missing = 0); worst case no stack. Tested on fixtures, not a live file.
- **Over/under-counting tokens**: dedupe assumes one message's lines are consecutive; if
  not, a message may count twice. Acceptable for a tiered stack.
- **SVG cost** with many sprites: run-merged paths keep DOM small; checked with a floor
  of 16 desks in the preview.
- **Art legibility at 1x** (8×11 characters): rendered at ×4–×5 on the floor; the
  miniature uses ×2. Not checked visually yet → the ui-verifier pass must look at it.
- **Generated file size**: ~40 sprites at 1x is a few tens of KB of strings.
