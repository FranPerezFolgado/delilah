# Brief: Playground redesign (per-task office + flow view)

Input for the next `/feature`. The current Playground (spec 004, merged with main's
UI v2 at 1567d2a) works but the user doesn't like how it looks. Decided on 2026-10-26:

## Decisions

1. **Where**: each task gets its own office floor in a tab of its task screen, and the
   Playground becomes a **building**: one small floor per live task (overview);
   clicking a floor opens that task's floor.
2. **Flow view in this iteration**: a toggle Office ↔ Flow in the same place. Flow is
   an agent-flow style live graph for the task: agent → tool calls → subagents, with a
   timeline. Needs a short **in-memory history of activity events per session**
   (e.g. last ~200), which the daemon doesn't keep today (activity is live-only,
   decision #80 → to be revised).
3. **Art: port pixtuoid's** (MIT, © 2026 Ivan Wang, no third-party art), with the
   notice in `app/src/playground/CREDITS.md`.

## Ideas to carry over

- State on the desk, not only the pose: monitor glow colour per tool; `?` when it
  needs you; zzz when idle/paused; paper stack for tokens.
- Subagents get their own desk in the task's floor (boss + team), and go to the
  lounge/pantry when they finish.
- Same project → same outfit colours.
- Ambient (optional, later): day/night skyline, pet, sound with mute.

## Keep from the current implementation

Daemon activity (hooks, `/api/v1/activity`, `activity` topic, helpers, captions cut at
40 chars), slots that never move, accessible names, reduced motion, stale/hidden
pause, the separate window, main's UI v2 conventions (per-component CSS and
`i18n/en/<Component>.ts`, tokens, ≥12px type).
