# Data model: Public repo onboarding

No database or API change. The feature works with these existing or file-level entities.

## Language setting (existing)

- Stored by the daemon as the `language` preference: JSON string, written by Settings.
- Valid values: `"auto"` (default when missing), `"es"` or `"en"`. Any other stored value is
  treated as `"auto"` when read. It is not rewritten.
- Resolves to `Lang = "es" | "en"` by the rule in [contracts/language.md](contracts/language.md).

## Release (extended)

- Identified by its tag `vX.Y.Z` on `main`.
- Assets are listed in [contracts/release-assets.md](contracts/release-assets.md); this feature
  adds `SHA256SUMS` and a provenance attestation (stored by GitHub, linked to the assets'
  digests).
- States (unchanged): draft → published (latest). The new steps run while it is a draft.

## Changelog entry (new file)

- One `## [X.Y.Z] - YYYY-MM-DD` section per tag, generated by git-cliff from Conventional
  Commits, grouped by type (Features, Fixes, Docs, Refactor, Performance, Other). Version
  bump and merge commits are skipped.
- Invariant (checked by `scripts/release/check.mjs`): the version being released has a section.

## Doc set (reorganised)

- **Current**: README.md, docs/README.md, docs/usage.md, docs/architecture.md,
  docs/decisions.md, docs/development.md, docs/status.md, docs/vision.md, and the root community
  files. English only, English UI labels, no private links, no relative link that doesn't
  resolve.
- **History**: specs/, .specify/, docs/redesign/, docs/archive/. Kept as written, each
  labelled by a README.
